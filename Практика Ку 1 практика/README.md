# Эмулятор оболочки (GUI + VFS)

Учебный эмулятор UNIX-подобной командной строки на Python с графическим интерфейсом (`tkinter`). Работает с виртуальной файловой системой (VFS), которая загружается из XML-файла и целиком хранится в памяти.

## Требования

- Python 3.9+ (проект разработан на Python 3.14)
- `tkinter` (входит в стандартную поставку Python для Windows)
- Сторонние библиотеки не нужны

## Запуск

```
python "Console thatwillwork1.py" [--vfs ПУТЬ_К_XML] [--script ПУТЬ_К_СКРИПТУ]
```

| Параметр | Описание |
|---|---|
| `--vfs` | путь к XML-файлу с описанием VFS |
| `--script` | путь к стартовому скрипту с командами эмулятора |

Оба параметра необязательны. Примеры:

```
python "Console thatwillwork1.py"
python "Console thatwillwork1.py" --vfs vfsdeep.xml
python "Console thatwillwork1.py" --vfs vfsdeep.xml --script Start_script.txt
```

Имя файла эмулятора содержит пробел, поэтому в командной строке его нужно брать в кавычки.

## Этап 1. REPL

Минимальный прототип с диалогом с пользователем.

**Реализовано:**

- GUI на `tkinter`: окно с чёрной консолью, ввод только после приглашения (нельзя стереть вывод или приглашение).
- Заголовок окна формируется из данных реальной ОС: `username@hostname` (через `getpass.getuser()` и `socket.gethostname()`).
- Парсер строки на основе `shlex.split` (поддерживает кавычки) с раскрытием переменных окружения реальной ОС: `$HOME` и `${HOME}`. Неизвестная переменная раскрывается в пустую строку.
- Сообщения об ошибках: неизвестная команда, ошибка разбора (например, незакрытая кавычка), неверные аргументы.
- Команды-заглушки `ls` и `cd` (на этом этапе выводят имя и аргументы).
- Команда `exit` закрывает окно.

**Примеры работы:**

```
user@host:~$ ls -l /tmp
ls, аргументы: ['-l', '/tmp']
user@host:~$ cd $HOME
cd: ['C:\\Users\\user']
user@host:~$ foo
foo: команда не найдена
user@host:~$ cd "abc
ошибка: No closing quotation
user@host:~$ exit
```

## Этап 2. Конфигурация

Эмулятор настраивается параметрами командной строки (`argparse`).

**Реализовано:**

- Параметры `--vfs` и `--script`.
- Отладочный вывод всех заданных параметров при запуске:
  ```
  [отладка] параметры запуска:
    vfs    = vfsdeep.xml
    script = Start_script.txt
  ```
- Стартовый скрипт: команды выполняются последовательно, пустые строки и строки с `#` пропускаются, **ошибочные строки не прерывают скрипт**. На экране показывается и ввод (с приглашением), и вывод, как в живом диалоге.
- После скрипта эмулятор остаётся в интерактивном режиме. `exit` внутри скрипта корректно закрывает окно.
- Скрипты ОС (`.bat`) вызывают эмулятор с разными комбинациями параметров: оба, только `--vfs`, только `--script`, без параметров, несуществующий скрипт.

## Этап 3. VFS

Подключена виртуальная файловая система.

**Реализовано:**

- Источник VFS: XML-файл (формат описан [ниже](#формат-xml-для-vfs)). Бинарные данные хранятся в base64.
- Все операции выполняются **в памяти**: файл читается через `ET.parse` в дерево объектов `VNode`, ничего не распаковывается и не записывается на диск.
- Сообщения об ошибках загрузки VFS:
  - файл не найден;
  - неверный формат XML;
  - неверный корневой элемент (должен быть `<vfs>`);
  - неверное или повторяющееся имя узла, неизвестный тег, неверный base64.

  При ошибке эмулятор выводит сообщение и продолжает работу с пустой VFS.
- Динамическое приглашение с текущим каталогом VFS: `user@host:/home/user$ `.
- Разрешение путей: абсолютные (`/a/b`), относительные, `.` и `..`.
- Скрипты ОС для разных VFS: минимальной (`vfsminimal.xml`), с несколькими файлами (`vfsseveral.xml`), с 3+ уровнями вложенности (`vfsdeep.xml`), а также для ошибок (`vfsbroken.xml`, несуществующий файл).
- Стартовый скрипт `Start_script.txt` проверяет все команды этапов 1-3, включая ошибки.

## Этап 4. Основные команды

Команды в стиле UNIX, работающие по VFS.

### `ls [путь]`

Выводит содержимое каталога (каталоги с `/` на конце, по алфавиту). Для файла выводит его имя.

| Режим | Пример |
|---|---|
| без аргументов (текущий каталог) | `ls` |
| относительный путь | `ls docs` |
| абсолютный путь | `ls /home/user` |
| на файле | `ls a.txt` |

Ошибки: путь не найден, неизвестная опция (`ls -la`), слишком много аргументов.

### `cd [путь]`

Переходит в каталог. Без аргументов возвращает в корень.

| Режим | Пример |
|---|---|
| в подкаталог | `cd docs` |
| на уровень вверх | `cd ..` |
| абсолютный путь | `cd /home/user/projects` |
| в корень | `cd` |

Ошибки: путь не найден, это файл, слишком много аргументов.

### `tail [-n N] файл...`

Выводит последние `N` строк файла (по умолчанию 10).

| Режим | Пример |
|---|---|
| 10 последних строк | `tail /home/user/log.txt` |
| заданное число строк | `tail -n 3 /home/user/log.txt` |
| `-n 0` | `tail -n 0 /home/user/log.txt` |
| несколько файлов (заголовки `==> файл <==`) | `tail a.txt b.txt` |

Ошибки: не указан файл, файл не найден, это каталог, `-n` без числа, неверное или отрицательное число, неизвестная опция.

### `wc [-l] [-w] [-c] файл...`

Считает строки, слова и байты.

| Режим | Пример |
|---|---|
| все счётчики | `wc /home/user/log.txt` |
| только строки / слова / байты | `wc -l f`, `wc -w f`, `wc -c f` |
| комбинация опций | `wc -lw f` |
| несколько файлов (с итогом `total`) | `wc a.txt b.txt` |

Ошибки: не указан файл, файл не найден, это каталог, неизвестная опция.

### Тестирование

Стартовый скрипт `Start_stage4.txt` содержит примеры всех режимов команд и ошибок:

```
python "Console thatwillwork1.py" --vfs vfsdeep.xml --script Start_stage4.txt
```

## Этап 5. Дополнительные команды

Команды, изменяющие VFS. Изменения делаются **только в памяти**: исходный XML-файл на диске не меняется.

### `rmdir каталог...`

Удаляет пустые каталоги.

| Режим | Пример |
|---|---|
| один каталог | `rmdir /tmp/a/b` |
| несколько каталогов | `rmdir /tmp/a /home/user/projects/app/empty` |

Ошибки: не указан каталог, путь не найден, это не каталог, каталог не пуст, попытка удалить корень, текущий каталог или его родителя.

### `rm [-r] путь...`

Удаляет файлы. С `-r` (или `-R`) удаляет каталоги вместе с содержимым.

| Режим | Пример |
|---|---|
| файл | `rm /etc/config.cfg` |
| несколько файлов | `rm /etc/config.cfg data.bin` |
| каталог рекурсивно | `rm -r /home/user/projects` |

Ошибки: не указан путь, путь не найден, каталог без `-r`, неизвестная опция, попытка удалить корень, текущий каталог или его родителя.

### Тестирование

Скрипт `Start_stage5.txt` изменяет VFS по шагам и проверяет результат командами `ls` и `tail`, а в конце проверяет все ошибки:

```
python "Console thatwillwork1.py" --vfs vfsdeep.xml --script Start_stage5.txt
```

## Формат XML для VFS

```xml
<vfs>
  <file name="readme.txt">Текстовый файл</file>
  <file name="data.bin" encoding="base64">SGVsbG8gV29ybGQ=</file>
  <dir name="docs">
    <file name="a.txt">текст</file>
    <dir name="empty"></dir>
  </dir>
</vfs>
```

- Корневой элемент: `<vfs>`.
- `<dir name="...">` это каталог, `<file name="...">` это файл.
- Имя обязательно, не должно содержать `/` и не должно повторяться внутри одного каталога.
- Содержимое файла хранится как текст. Для двоичных данных используется `encoding="base64"`.

## Тестовые скрипты

Скрипты ОС (`.bat`) запускают эмулятор с разными вариантами VFS и параметров. В PowerShell запускать с `.\`:

| Скрипт | Что проверяет |
|---|---|
| `test_minimal.bat` | минимальная VFS |
| `test_several.bat` | VFS с несколькими файлами и base64 |
| `test_deep.bat` | VFS с 3+ уровнями вложенности |
| `test_vfs_not_found.bat` | ошибка «файл не найден» |
| `test_vfs_broken.bat` | ошибка «неверный формат XML» |
| `test_no_vfs.bat` | запуск без `--vfs` (пустая VFS) |
| `test_stage4.bat` | `tail`, `wc` и ошибки |
| `test_stage5.bat` | `rmdir`, `rm` и ошибки |

Пример содержимого `.bat`:

```bat
@echo off
python "Console thatwillwork1.py" --vfs vfsdeep.xml --script Start_stage4.txt
pause
```
